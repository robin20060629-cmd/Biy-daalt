# Алдаа 2 · Боолийн флагийн антипаттерн
do_user_op(obj, flag, timeout) — flag: 0=create, 1=update, 2=delete, 3=restore гэж нэг методод 4 өөр үйлдлийг шилжүүлж байсан. Дуудагч flag=2 гэж бичихэд юу болохыг тайлбараас уншихаас өөр аргагүй байсан.
Засвар: createUser, deleteUser гэх мэт тусдаа методуудад хуваасан.
# Алдаа 3 · Мэдээллийн далдлалт зөрчсөн
public db_conn, public users_arr — гадны кодоос шууд өөрчлөх боломжтой байсан.
Засвар: private databaseConnection, private users болгосон.
# Алдаа 4 · Стрингтэй алдааны тэмдэглэгээ
get_u нь хэрэглэгч олдоогүй үед 'ERR_404' гэсэн magic string буцааж байсан. Хөрвүүлэгч алдааг барьж чадахгүй байсан.
Засвар: UserNotFoundException тусгай алдаа шидэх болгосон.
# Алдаа 5 · any төрлийн хэт ашиглалт
obj: any, db_conn: any, Array<any> — TypeScript-ийн статик шалгалтыг бүхэлд нь унагааж байсан.
Засвар: User interface, User[] тодорхой төрлүүд ашигласан.
# Алдаа 6 · find методын тодорхойгүй нэр ба ойлголтын жин
find(q) — нэр нь хэтэрхий ерөнхий, q параметр нь ямар утгатайг мэдэгдэхгүй. Exception translation хийгдээгүй байсан.
Засвар: findUsers(query) болгож, try/catch-ээр дотоод алдааг library-ийн алдаа болгон хувиргасан.



### А.2 Rate Limiter Library

Энэхүү сан нь системд ирэх хүсэлтийн тоог хязгаарлах зориулалттай бөгөөд "3-ын дүрэм"-ийн дагуу 1 интерфейс, 3 хэрэгжилт (одоогийн байдлаар FixedWindow-ийг бүрэн хэрэгжүүлсэн), болон Factory паттерныг ашиглан зохион бүтээгдсэн.

### 1. Дизайны шийдвэр (Design Decisions)
Interface-based Design:** `RateLimiter` интерфейсийг тодорхойлж, нийтийн (public) бүх функцуудыг энд төвлөрүүлсэн. Энэ нь санг ашиглаж буй талд хэрэгжүүлэлтийн нарийн ширийнийг мэдэх шаардлагагүй болгож, "Loose Coupling" зарчмыг хангасан.
Factory Pattern:** `LimiterFactory` классыг ашиглан объектуудыг үүсгэдэг. 
Encapsulation:** Хэрэглэгч зөвхөн интерфейсээр дамжуулж харьцах ба дотоод логик болон өгөгдлийн бүтэц (Map) нь `private` түвшинд хамгаалагдсан.

### 2. Сангийн бүтэц (Folder Structure)
`api/`: Нийтийн интерфейс болон Factory класс.
`impl/`: Алгоритмын бодит хэрэгжүүлэлтүүд (Fixed Window гэх мэт).
`test/`: Сангийн тогтвортой байдлыг шалгах 15 unit test.

### 3. Алдаа боловсруулалт (Exception Handling)
Сан нь өөрийн гэсэн `LibraryException` (эсвэл системд тохирсон алдаа)-ийг ашиглан буруу тохиргоо эсвэл зөвшөөрөгдөөгүй утга орж ирэх үед алдааг мэдээлдэг.

### 4. Тестлэлт (Unit Testing)
Нийт 15 unit test бичсэн бөгөөд үүнд:
 Хязгаар хүртэл зөвшөөрөх тохиолдол.
 Хязгаар давсан үед хүсэлтийг хаах логик.
 Олон хэрэглэгч (clientId) зэрэг хандах үеийн бие даасан байдал.
 Factory-ийн зөв ажиллагаа болон Edge case-үүдийг шалгасан.
